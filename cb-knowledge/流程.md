# 流程

> Cookbook / ItemV2 常见业务流程，一句话版。字段和对象含义见 [基础知识](./基础知识.md)。

## 造一个可发布的 Menu Item

**建草稿 Menu Item → 加一个 Component → 配 Concept / Service Setting / Nutrition / Packaged SKU → Publish。**

（顺序有依赖：先加组件才会出现 Packaged SKU；Nutrition Reviewed 要在录完营养值后最后打开。对应组合 flow：`buildFullMenuItem`（用已有组件）/ `assembleFullMenuItem`（连组件也现造）。）

## Menu 能 Publish 的前置条件（40* / 42* item）

Menu 的 component 是 40* item（HDR Recipe / HDR Consumable）。**40* item 要能 publish，必须满足：**

1. 在 Cookbook 这边创建一条 40* item；
2. 把它关联到 **SCC 系统里一条 Active 的 42* item**。

42* item 本身以及它的状态（Active 与否）都由 **SCC 系统控制**，Cookbook 里改不了，e2e 也造不出来。
所以 e2e **不能自己造一个能 publish 的 40**，只能引用**已经存在且已发布的 40**（QA 上现成的）。

> 目前暂用的现成 component（QA，HDR Consumable，状态 Final）：`4001164`（Tomato Confit(V1 Final)）；同名带 `[FZN]` 的是 `4001164F`。
> 用它们做 Menu 的 component（`buildMenuWithComponent` 默认 `4001164`），不要尝试 API 造 40 来发布。
> 另：自己用 API 创建的 e2e 40* item（`createHdrConsumable`）**自己是可以发布的**（已验证：补上 Out of Stock Name 后
> `publishHdrConsumable` 发布成功，状态 FINAL）。但没有关联 Active 42 的 40 被 **Menu 用作 component 时**，Menu 的发布校验
> 预计会报 "Active WSKU in Component (Missing)"（后端 `ValidationInformationTips`，MD-18520）——这一条是读代码推断，**还没在 QA 上验证**。
> 所以 Menu 的 component 仍用现成的已关联 42 的 40（如 `4001164`）。

## Menu Publish 的校验与弹窗

- 发布前可用 `PUT /ajax/v2/item/version/:id/check-for-publish`（body `{service_start_time:null, production_start_time:null}`）查缺什么，
  看返回里的 `validation_information.invalid_info_list`；`required:true` 才会拦发布，`required:false` 只是 warning。
- **Line Build 缺失只是 warning**（`required:false`），不拦发布：UI 会弹 "Incomplete info"，点 **Publish anyway** 继续。
- 真正拦发布的会弹 **"Unable to Publish"**（按钮 Confirm）；例如 Menu 的 **Nutrition (missing)**。
- **Menu 的 Nutrition 和 Recipe 不是同一份数据**：Menu 存在 `itemCustomizationNutrition`（接口 `customization/nutrition`），
  Recipe/Benchtop 才用 `recipe/nutrition`。用错接口调用会成功，但 Menu 仍被判 "Nutrition (missing)"。
- 校验信息由后端监听数据变更后异步重算，改完数据后读校验结果可能有短暂延迟。
- `publishMenuItem` 现在不再无条件返回 published:true，而是用 API 读回版本状态（FINAL 才算成功）。

## 其他流程（一句话）

- **建 → 搜 → 删（自清理）**：建个 item，按名字搜到，再删掉，跑完不留垃圾 → `createSearchDeleteItem`。
- **给已有 item 加组件**：进详情页 BOM 编辑器，搜到组件、填 Usage、保存 → `addComponentToItem`。
- **发布 HDR Consumable**：先填必填的 Out of Stock Name，再 Publish → `publishHdrConsumable`。

> flow 的完整参数 / 返回值以 [`flows/FLOWS.md`](../flows/FLOWS.md) 为准；运行时用自然语言告诉 agent 意图即可（如「造一个 Menu Item，把 4000470 作为组件」）。
